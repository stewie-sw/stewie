# STEWIE shared-core lunar QGIS project (`gis/`)

Phase-1 keystone of the STEWIE QGIS pivot: one QGIS project in which the Artemis
south-pole candidate sites (85–90°S) are ordinary, float-queryable, pole-truthful
GIS. Project CRS is **`IAU_2015:30135`** (Moon 2015 South Polar Stereographic,
sphere R = 1 737 400 m, `+proj=stere +lat_0=-90 +lon_0=0 +k=1 +R=1737400`); the
pole is the middle of the canvas, not a mercator wall.

Built and verified with **QGIS 3.22.16** (system `/usr/bin/python3` PyQGIS) and
**GDAL 3.6.2** on archimedes. Headless everything: `QT_QPA_PLATFORM=offscreen`.

> Scope of this project now spans **P1.2/P1.6** (DEM + hillshade + slope COGs, the
> verified core), **P1.4** (real site vectors — labeled pins + footprint polygons
> derived from the COG extents), **P1.3** (external imagery/OGC services as
> render-probed WMS layers — LROC NAC South Pole mosaic + WAC global + PSR via
> Lunaserv, the live STEWIE `/ogc` connection), and **P1.5** (the ARTEMIS_LAYERS
> catalog mirrored into layer-tree groups + provenance). Every ARTEMIS_LAYERS row
> is either loaded or explicitly deferred with a reason — see **`LAYER_STATUS.md`**.

## Data files and sources

Sources are as documented in the STEWIE QGIS pivot plan §1 and `ARTEMIS_LAYERS.md`.
All rasters are **Float32**, native `IAU_2015:30135`, COG (DEFLATE + internal
overviews). Site DEM/slope are 5 m/px; Haworth is 1 m/px.

- **Site DEMs + slopes** — PGDA **Product 78** LOLA 5 m polar-stereographic DEMs
  (LOLA/LDEM lineage). Slope is in **degrees**, derived from each site DEM.

## Rebuild the project

Requires the source COGs in place at `/mnt/projects/stewie/data/gis/cog/`. The
build is idempotent (deletes and rebuilds the `.qgz`, regenerates hillshades and
the proof PNGs):

```bash
cd /mnt/projects/stewie/code/gis
QT_QPA_PLATFORM=offscreen /usr/bin/python3 build_project.py --date 2026-07-05
```

`--date` stamps layer provenance (`QgsLayerMetadata`); pass it explicitly for a
reproducible build. Options: `--data-root`, `--output`, `--no-proof`.

What it does:
- sets project CRS `IAU_2015:30135` and the **measurement ellipsoid** to the Moon
  sphere (`PARAMETER:1737400:1737400`) so measure tools never assume WGS84;
- loads all 17 COGs as raster layers, grouped per site (+ a Haworth group), each
  explicitly tagged `IAU_2015:30135` (no layer is EPSG:4326 — MA-01);
- styles DEM = per-site hypsometric pseudocolor (real min/max), slope = discrete
  pseudocolor classed at mobility breaks **5 / 10 / 15 / 20°** (IPEx envelope: 15°
  nominal, 20° slope-test), hillshade = grayscale;
- generates a per-DEM hillshade via `processing.run("gdal:hillshade", …)` in the
  polar-stereo frame (correct at the pole), added under each DEM;
- writes provenance (source file, generating command, date) into each layer's
  `QgsLayerMetadata`;
- **(P1.4)** derives `../../data/gis/vectors/artemis_sites.geojson` from the real
  COG extents — one labeled pin at each DEM centre + a densified footprint polygon
  per site, in `IAU_2015:30100` lon/lat, `site` ids matching the backend naming
  (`Site01/04/06/07/11/20/23/42`) — and adds them as styled vector layers;
- **(P1.3)** render-probes the external OGC services and adds the ones that render
  (LROC NAC South Pole mosaic + WAC global + PSR via Lunaserv `wms.im-ldi.com`, the
  live STEWIE `/ogc` connection) as WMS layers, relabeled to the lunar geographic
  datum `IAU_2015:30100` so QGIS reprojects lunar→lunar onto the polar canvas (no
  Earth claim); unreachable/unrenderable services are deferred (see `LAYER_STATUS.md`);
- **(P1.5)** groups everything into `base.* / terrain.* / vector.*` catalog groups
  and writes `LAYER_STATUS.md` + `layer_status.json` (the gate-5/gate-6 report);
- saves `stewie_south_pole.qgz` (32 layers) and renders `proof/site01_render.png`,
  `proof/site04_render.png`, and `proof/site01_with_imagery.png` (the NAC drape +
  Site01 terrain + site vectors over Site01).

### External services (P1.3) — honest status

The NAC South Pole mosaic and WAC global context render cleanly (Lunaserv WMS is
requested over its EPSG:4326 wire grid, then the QGIS layer is relabeled to the
lunar `IAU_2015:30100` — same numeric lon/lat, no Earth datum). **Deferred, with
reasons in `LAYER_STATUS.md`:** Moon Trek WMTS (its tile-matrix CRS `EPSG:104903`
does not resolve in QGIS 3.22's bundled PROJ), QuickMap (proprietary SPA, no public
OGC caps), and the STEWIE `/ogc` in-canvas render (the server returns a real tile —
curl-verified — but QGIS 3.22 culls the GetMap because `ogc.py` advertises no
per-CRS `BoundingBox`; the connection is present, the fix is a P2.0 backend change
outside `gis/`).

## Run the acceptance tests (P1 gate 7)

`test_project.py` is a valid pytest module **and** a standalone runner. On this
host the only PyQGIS-capable interpreter is system `python3.11`, which has no
pytest (PEP-668 blocks a clean install; the pre-existing `~/.local` pytest is a
broken empty namespace package). Run it directly — it executes the identical
`test_*` functions and locks the process exit code:

```bash
cd /mnt/projects/stewie/code/gis
QT_QPA_PLATFORM=offscreen /usr/bin/python3 test_project.py   # exit 0 = all pass
```

In a QGIS + pytest CI container it runs as normal pytest:

```bash
QT_QPA_PLATFORM=offscreen pytest test_project.py -v
```

Tests (real assertions on real data, no synthetic values):
- **Gate 1** `test_pole_renders_not_black` — Site01 (89.46°S) and Site04 (89.77°S)
  render DEM+hillshade+slope; asserts non-black + luminance variance.
- **Gate 3** `test_value_readout_fidelity` — 51 spot pixels across all 17 COGs;
  QGIS `dataProvider().sample()` equals `gdallocationinfo -valonly` (Float32-exact,
  max observed |diff| 5e-12).
- **Gate 4** `test_measurement_polar_tolerance` — per-site extent measured in the
  metric 30135 frame equals the gdal extent exactly; the true Moon-sphere ground
  distance is within the polar-stereo scale tolerance `k = 2/(1+sin|φ|)` (≤0.2% at
  85°S, →0 at the pole).
- **Gate 5** `test_gate5_artemis_rows_all_accounted` *(pure python, no QGIS)* — every
  ARTEMIS_LAYERS row is a loaded layer or a deferred row with a reason + URL.
- **Gate 6** `test_gate6_status_json_consistency` *(pure python)* + `test_gate6_
  connections_render_from_saved_project` *(QGIS)* — the connections recorded as
  `renders` carry a real non-blank tile (NAC ≈ 0.67), are in the saved `.qgz`, and
  the `site01_with_imagery.png` proof is non-black.
- **P1.4** `test_site_vectors_roundtrip` *(QGIS)* — the 8 site pins load in 30100,
  ids match the backend naming, and each pin round-trips 30100↔30135 inside its own
  DEM footprint.
- `test_project_crs_and_no_earth_claim` — project CRS `IAU_2015:30135`, Moon-sphere
  ellipsoid; **32 layers = 26 terrain (30135) + 2 vectors (30100) + 4 external WMS
  (relabeled 30100)**; none EPSG:4326/WGS.

QGIS-dependent tests are guarded with `pytest.importorskip("qgis")` so they SKIP in
a no-QGIS CI lane and RUN here; the gate-5/gate-6 registry+json tests are pure python
and always run. Current result on this host: **8/8 passed** (standalone, exit 0).
