# STEWIE Capability Matrix — honest status

> One place for the truths that are otherwise scattered across `PRD.md` rows, env docstrings, and
> `[CALIB]`/`[UNKNOWN]` tags. Three columns: **shipped & load-bearing** (real, wired, test-backed) /
> **training-only or offline** (real code, but NOT in the deployed product path) / **unbuilt & gated**
> (named in the PRD, deferred or externally blocked). Claims are grounded in `file:line`; if a row here
> disagrees with the code, the code wins — fix the row.
>
> The single honest headline: **STEWIE is a mature construction *planner + trainer + digital twin* on an
> unusually honest conserved-physics core. It is not yet an operational mission-operations console**, and
> does not claim to be. The deployed planner is deterministic on purpose; RL is training-only; the
> Execute playback is a sim run (no live telemetry).
>
> **Verified baseline 2026-07-01:** the configured suite collects **3179 tests**, coverage **89.7%**
> against the 85% CI gate; ruff clean; CI green (lint + type + coverage on py3.11, a py3.12/3.13 test
> matrix, and the browser-JS `node --test` tier). The public deploy **`app.stewie.space` is up** and
> serves the six-slot ConOps cockpit (Plan · Rehearse · Validate · Release · Execute · Report) plus
> the **`/program` requirement board**. The requirement matrix (PRD §7, 188 rows) reads
> **97/188 verified done — 56.1% of the 173 in-scope rows** (15 rows are hardware / host / external-data
> gated); the committed matrix is projected read-only onto `/program` by
> `scripts/gen_program_snapshot.py`, and `STATUS.md` is generated by `scripts/gen_status.py`
> (134 rows cited by a `[REQ:]` test). The actionable backlog is **PRD §27**. This narrative matrix
> is still hand-maintained; the code wins on any disagreement.
